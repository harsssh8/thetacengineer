Lab: TCP Handshake Analysis

Capture and annotate the three-way handshake, option negotiation and connection teardown on an isolated two-VM lab.

Networking & Protocols·Planned·Lab plan·Planned

    01Lab objective

    Capture, decode and annotate a complete TCP connection lifecycle: the three-way handshake, option negotiation (MSS, window scaling, SACK, timestamps), data transfer, and both graceful (FIN) and abortive (RST) teardown.

    02Environment

    ItemDetail
    HypervisorVirtualBox or VMware Workstation Player (free)
    lab-clientUbuntu Server 24.04, 192.168.56.10
    lab-serverUbuntu Server 24.04 with Nginx, 192.168.56.20
    NetworkHost-only network, isolated from any production network

    04Architecture diagram

    05Implementation steps

    1. Build the two VMs on a host-only network and confirm reachability with ping.
    2. Install Nginx on lab-server and confirm it is listening with ss -ltnp.
    3. Start a capture on lab-server.
    4. Generate a single HTTP request from lab-client with curl.
    5. Repeat with a refused port (nc -vz 192.168.56.20 81) to capture SYN → RST.
    6. Annotate the capture in Wireshark: sequence and acknowledgement numbers, flags, and each negotiated option.
    bash — planned commands
    # lab-server
sudo tcpdump -i enp0s8 -nn -w handshake.pcap 'host 192.168.56.10 and (port 80 or port 81)'

# lab-client
curl -s -o /dev/null -w '%{http_code}\n' http://192.168.56.20/
nc -vz 192.168.56.20 81

    06Validation

    The lab is complete when the write-up shows, with annotated screenshots:

    • SYN, SYN/ACK and ACK with correct relative sequence and acknowledgement numbers.
    • The MSS, window scale, SACK-permitted and timestamp options offered by each side.
    • The four-segment FIN/ACK teardown and which side entered TIME_WAIT.
    • The SYN → RST exchange for the closed port.
    Annotated Wireshark screenshots will be added here after the lab is completed.
